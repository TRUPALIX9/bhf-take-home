![PO Review dashboard](docs/screenshots/list.png)

Both parts use purchase orders as their subject. The Next.js app reviews POs; the Python script turns a vendor PO into a spreadsheet. The folders are independent and each has its own README. The only link is data: the Python script's JSON output for the sample PO is the app's seed for TX9K2QP.

## Repository layout

```
bhf-take-home/
├── technical-assessment/   what BHF sent: both PDFs, sample PO, output template, requirement map
├── nextjs-app/             Part A: Next.js 15 PO review app (own README and CLAUDE.md)
├── python-po-parser/       Part B: PO text → spreadsheet script (own README and CLAUDE.md)
├── docs/
│   ├── DESIGN.md           system overview, lifecycles, flows (Mermaid diagrams)
│   └── screenshots/        README images, regenerated by `npm run screenshots`
├── scripts/check.sh        every check for both parts, the same one CI runs
├── .github/workflows/      CI: runs scripts/check.sh on every push
├── .claude/                Claude Code reviewer agent and /check skill
└── CLAUDE.md               shared instructions for the AI assistant
```

## Run every check

```bash
scripts/check.sh
```

Lint, typecheck, unit tests, build and Playwright for the app; ruff, pytest and a run on the sample for the parser; and a check that the parser's input files match the originals in `technical-assessment/`. Prefix with `PW_CHANNEL=chrome` to run the browser tests on an installed Google Chrome.

Design notes and diagrams: [`docs/DESIGN.md`](docs/DESIGN.md).
